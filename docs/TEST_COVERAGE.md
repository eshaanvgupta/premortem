# Validation evidence map

Actual executed results belong in the generated validation/readiness report; this document maps requirements to checks rather than inventing a final tally.

| Layer                | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Solidity             | Foundry tests cover holder gates, phases, independent/duplicate votes, commitment domains, invalid inputs, finalization, events and bounded storage. See `packages/contracts/test` and the actual Foundry output.                                                                                                                                                                                                                                        |
| Deterministic core   | Vitest and property tests cover exact calldata, integer precision, canonical/domain hashing, rule findings, RPC failures, event scanning and receipt consistency. Test providers remain test-only.                                                                                                                                                                                                                                                       |
| Local wallet adapter | `packages/cli/test/adapter.test.ts`: 36 executed tests passed during initial implementation, including disabled/expired mode, preview error, simulation failure, user rejection, pre/post-confirmation expiry, successful request-ID binding, pending App confirmation, no execute retries, redaction, strict action JSON, compiled Solidity ABI compatibility and parsed-preview destination/source/value/chain/calldata binding. Re-run after changes. |
| Live read-only RPC   | `docs/evidence/live-readonly-preflight.json`: actual mainnet chain 56 response, official Agent ID runtime code, exact empty-calldata call/gas failures, explicit unknown findings. This neither broadcasts nor proves a holder write.                                                                                                                                                                                                                    |
| Browser              | Root project Playwright suites and screenshot artifacts report actual routes, mobile/keyboard, read-only errors and test-only local wallet/provider workflows where exercised. Do not describe unexecuted scenarios as passed.                                                                                                                                                                                                                           |
| Release              | Strict TS, lint, formatting, production build, dependency scan, secret scan, Docker/Foundry/anvil/static-analysis availability and actual results are reported separately.                                                                                                                                                                                                                                                                               |

All mocked providers/identities are confined to test paths. Production has no seed capsules, fake reviewer quotes or simulated participant count. E2E wallet stubs demonstrate software boundaries, not actual Agentic Wallet compatibility. A real wallet signing run, deployment, explorer verification and hosted-origin checks remain external prerequisites until explicitly approved and performed.
