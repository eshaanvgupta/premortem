# Limits and external requirements

Mainnet deployment, BscScan verification, public repository publication, public site publication and actual Agentic Wallet signing require the operator's explicit approval and/or credentials. None may be inferred from a local build. Deployment addresses and transaction hashes remain unknown until real broadcasts and successful receipts exist. No eligible participants can be measured for an undeployed protocol; an unconfigured or partial scanner must show unavailable/partial, not an invented zero or a campaign qualification claim.

Agent ID `balanceOf` is the documented access test. Verified source inspection of its implementation was unavailable during initial browser research. Its nontransferability is stated by the organizer, not mathematically proven by PREMORTEM. Addresses do not establish unique humans; issuer changes or lookup failure can affect access. A bounded staticcall should be checked against the live official registry before deployment authorization.

The official wallet preview guide does not guarantee raw source/chain/calldata echoes for arbitrary custom calls. The adapter compares all recognized echoed fields and requires a parsed matching destination and zero value; missing or unfamiliar shapes fail closed. The exact locally encoded request and wallet preview are both shown, but the request ID's association with omitted raw fields is trusted to the official wallet backend. An actual holder's first live custom-call preview may reveal an unsupported schema and require adapter review before signing. This is an explicitly unverified wallet compatibility prerequisite, not a mocked working connector.

Generic calldata analysis cannot establish safety. The engine covers recognized selectors and defined heuristics, not all protocols or indirect effects. Exact simulation may fail because of state, insufficient balance, permissions or provider limitations. Success at a block is not a promise about later execution. Trace support is optional. Metadata authenticity, off-chain assertions, evidence availability, honest review, collusion resistance and economic security remain outside the contract's guarantees.

On-chain evidence hashes do not force a reviewer to reference a true or meaningful observation. The product asks for category, confidence and evidence, but cannot prove their quality. Confidence is descriptive and does not weight votes. Inconclusive is a first-class outcome. The contract has no cancellation or edits; a mistaken public label and all actions remain public.

The default public dataseed RPC is suitable only where its actual capabilities permit. Official docs warn that mainnet `eth_getLogs` is disabled on listed public endpoints. Reading historic events needs a working keyless log provider or an independently operated node. All public endpoints can be throttled; total completeness depends on scanning the deployment range without gaps and verifying current canonical blocks.

No LLM is required. A shipped optional explanation feature must obtain explicit consent before disclosing wallet data and must label generated interpretation; it can never override deterministic checks or authorizations. If the UI does not expose such a feature, no claim of implemented LLM integration is made. IPFS/Arweave persistence is not promised without actual upload/pinning receipts.

This repository is an engineering implementation, not a formal audit, legal opinion, organizer endorsement or promise of award eligibility. Live identity-wallet custom-call compatibility and external public infrastructure remain launch checks. Any missing tool-based check is reported in the validation report rather than treated as a pass.
