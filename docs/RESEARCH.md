The [Agent ID BscScan page](https://bscscan.com/address/0x60b9262456de011f7d15a54cdd8c48baaa8b022f#code) could not be retrieved by the research browser. Thus source-level assumptions beyond the announcement's `balanceOf` interface and stated nontransferability remain unverified here. No enumeration, reverse lookup, names, token URI, or ownership permanence is assumed. Live RPC bytecode and ABI calls are checked independently when available; they are not a substitute for auditing its implementation.

Preview binding review: the official guide documents a generic parsed transaction example, not a guaranteed raw transaction echo for unknown custom contracts. The published official `@binance/agentic-wallet` 1.12.0 CLI source was inspected without authentication or execution: it forwards exact preview parameters and returns backend data. NEXORA requires a matching parsed destination (`contractAddress` or `to`) and zero `amount`/`value`, compares every recognized echoed source/network/calldata field, and rejects asset-operation parsing. Opaque or missing bindings fail closed. The request ID remains a trusted wallet-backend binding for omitted fields; live custom-call compatibility must be established with an actual consenting holder, and is not claimed from test fixtures.

The source announcement describes BNB Chain deployment; this project's stricter BSC mainnet 56 requirement follows the supplied engineering specification. No material conflict with the supplied official constraints was found. Public endpoint reliability, custom-call acceptance for this new protocol, verified third-party identity implementation, actual hosting and genuine participant acquisition still require live operational checks. Competitor implementation details have not been independently verified; submission comparisons describe NEXORA's own scope rather than asserting unverified deficiencies elsewhere.
